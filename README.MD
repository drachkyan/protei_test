## Эмулятор смс сервиса для мобильной сети

# Сборка и запуск

Для сборки нужно установить зависимости

```
sudo apt install liburing-dev pkg-config libsqlite3-dev
```

Сборка проекта

```
cmake -B build .
cmake --build build
```

Запуск (пока что доступны только следующие аргументы запуска)

Запуск сервера
``` 
./build/mnc_s -p 8085 -epc epc.json -bases bases.json
```

Запуск клиента
``` 
./build/ue -p 8085 -i 0.0.0.0 -imei 158863118273320 -imsi 12345601112233 -msisdn 89991112233 -x -10
```

Запуск тестов 
``` 
./build/run_tests 
```

# Возможности:

## Сценарии использования

### 1. Подключение к сети
Пользователь запускает UE с параметрами (IMSI, IMEI, MSISDN, координата, адрес сервера) и выполняет команду `activate`.
UE автоматически измеряет сигнал всех доступных базовых станций, выбирает наилучшую, проходит процедуру Attach и аутентификации.
После успешного подключения абонент зарегистрирован в сети и готов к работе.

---

### 2. Отправка SMS онлайн-абоненту
Оба абонента подключены к сети. Отправитель выполняет `send_message`, вводит номер получателя и текст.
Сообщение проходит через ENodeB на MME, который находит получателя в XLR и доставляет SMS на его базовую станцию.
Получатель мгновенно получает сообщение, отправитель получает статус `DELIVERED`.

---

### 3. Отправка SMS офлайн-абоненту
Отправитель отправляет сообщение абоненту, который ещё не подключён к сети.
MME обнаруживает что получатель офлайн и ставит задачу на ожидание — в течение TTL (по умолчанию 20 секунд) периодически проверяет не появился ли абонент в сети.
Получатель в это время выполняет `activate` и подключается.
Как только MME фиксирует появление абонента, SMS немедленно доставляется. Отправитель получает статус `DELIVERED`.
Если абонент не появился в течение TTL — отправитель получает статус `FAILED`.

---

### 4. Перемещение между базовыми станциями (Handover)
Абонент подключён к сети и выполняет команду `move`, смещаясь в зону покрытия другой базовой станции.
Фоновый поток UE периодически измеряет сигнал всех станций. Как только сигнал соседней станции превышает текущую на пороговое значение, автоматически инициируется процедура Handover.
Слот абонента переносится на новую станцию, MME обновляет привязку. Соединение не прерывается.

---

### 5. Выход за пределы зоны покрытия и переподключение
Абонент перемещается за пределы радиуса всех базовых станций — текущая станция пропадает из списка доступных.
UE обнаруживает потерю станции, выполняет полное отключение (очищает TMSI) и через небольшую паузу автоматически пытается переподключиться.
Если в новой точке есть покрытие — абонент снова проходит Attach и продолжает работу. Если покрытия нет — попытка повторяется.

---

### 6. Просмотр истории переписки
Абонент выполняет команду `open_chat` и вводит номер собеседника.
Отображается история отправленных и полученных сообщений с этим абонентом, а также статус каждого сообщения (`PENDING`, `SENT`, `DELIVERED`, `FAILED`).

---

### 7. Корректное отключение от сети
Абонент выполняет команду `deactivate` или `quit`.
UE отправляет на сервер запрос `DC` (Disconnect), MME очищает TMSI абонента в XLR, ENodeB освобождает слот.
Абонент считается офлайн — входящие SMS будут ожидать его повторного подключения в течение TTL.

# Структура программы

В корне лежат две папки UE и MNC отвечающие за клиентскую и серверную части соотвественно.
Также есть папка model в которой лежат общие для сервера и клиента модели (ue.context, коды ошибок и тд)

## UE (User Equipment)

Эмулятор мобильного устройства. Запускается как отдельный процесс и подключается к серверу MNC-S.

### Модули

**Exchange** — модуль сетевого взаимодействия с сервером.
- Управляет TCP соединением через `NetworkClient`
- Содержит два фоновых потока: `runThread` (приём сообщений) и `signalThread` (мониторинг сигнала)
- Реализует механизм запрос-ответ через `std::promise/future` с таблицей ожидающих запросов `pending`
- Обрабатывает процедуры Attach, Auth, Handover, SMS
- При потере сигнала автоматически переподключается к лучшей базовой станции

**ExchangeHandler** — обработчик входящих сообщений от сервера (без id, то есть инициированных сервером).

**NetworkClient** — низкоуровневая обёртка над TCP сокетом.
- Отправка и приём JSON сообщений с префиксом длины (4 байта big-endian)
- Неблокирующий connect с таймаутом через `select`

**Menu** — консольный UI для ввода команд пользователем.
- Поддерживает команды: `activate`, `deactivate`, `move`, `send_message`, `open_chat`, `quit`
- Каждая команда реализована как отдельный класс наследник `AbstractMenuItem`

**Settings** — парсинг и хранение аргументов командной строки (`-p`, `-i`, `-imei`, `-imsi`, `-msisdn`, `-x`).

**AppContext** — контекст абонента. Хранит IMSI, IMEI, MSISDN, TMSI, координату, историю SMS.

---

### Модули

**UEconnection** — точка входа для TCP подключений от UE устройств.
- Принимает входящие соединения
- Маршрутизирует входящие JSON сообщения на нужный ENodeB по полю `ENode`

**ENodeB (ENODE)** — эмулятор базовой станции.
- Принимает запросы от UE и транслирует их на MME
- Хранит слоты (`TMSItoSlots`) — буферы входящих и исходящих SMS для каждого подключённого абонента
- Обрабатывает измерение силы сигнала в зависимости от координаты UE и радиуса покрытия
- Реализует процедуру Handover — передачу абонента между базовыми станциями
- Содержит очередь внутренних задач для межстанционного взаимодействия

**EnodeHandler** — обработчик запросов ENodeB.
- Внешние запросы от UE: `R` (RadioMeasure), `A` (Attach), `AR` (UpdateLocation), `M` (SMS), `H` (Handover), `SMSStatus`, `DC` (Disconnect)
- Внутренние задачи между станциями: `SM` (SendMessage), `RS` (ReceiveSMS), `SS` (SendSMS), `SMSStatus`

**MME (Mobility Management Entity)** — узел управления мобильностью.
- Пул потоков для параллельной обработки задач от ENodeB
- Управляет регистрацией абонентов, обновлением местоположения, маршрутизацией SMS
- Генерирует TMSI через внешний Python скрипт
- При недоступности адресата SMS ожидает его появления в сети в течение TTL

**MMEHandler** — обработчик запросов MME.
- `A` — Attach: проверка абонента в XLR, генерация TMSI
- `UL` — UpdateLocation: привязка абонента к ENodeB
- `M` — SMS: маршрутизация сообщения на нужную базовую станцию
- `H` — Handover: обновление привязки абонента к новой станции
- `SMSStatus` — доставка статуса сообщения отправителю
- `DC` — Disconnect: очистка TMSI абонента

**XLR** — модуль базы данных, эмулирует VLR и HLR.
- Реализован на SQLite через ORM
- Операции: поиск по IMSI/MSISDN/TMSI, обновление TMSI, обновление привязки к ENodeB, очистка TMSI

---

## Model (общие модели)

Используются как в UE, так и в MNC-S.

- **UEContext** — модель контекста абонента (IMSI, IMEI, MSISDN, TMSI, координата, SMS история)
- **SMSRecord / SMSMessage** — модели SMS сообщения
- **MessageStatus** — статус сообщения (`PENDING`, `SENT`, `DELIVERED`, `FAILED`)
- **StatusCodes** — коды ответов сервера и заготовленные JSON ответы

---

## Конфигурация

**epc.json** — конфигурация серверной части:
- `tmsi_script` — путь к Python скрипту генерации TMSI
- `ttl_sms` — время ожидания недоступного абонента (мс)
- `ttl_connections`, `ttl_ue_context` — TTL соединений и контекстов (зарезервировано)
- `hlr_path` — путь к SQLite базе данных
- `hlr_provider` — провайдер базы данных (sqlite)
- `xdr_provider` — куда писать логи (`console`, `file`, `both`)
- `xdr_path` — путь к файлу логов
- `xdr_pattern` — паттерн форматирования spdlog

**bases.json** — конфигурация базовых станций: id, координата, мощность, радиус покрытия.
